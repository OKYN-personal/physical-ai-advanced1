実行方法と提出前の確認
======================

１．内容
run_sorting.py        シミュレーション、CLIP推論、保留判断、位置推定、Panda制御、録画
test_suite.py         ４条件×３回の統計付き自動試験
test_logic.py         保留判断・射影・入力検査など11件の自動検査
calibration_probe.py  候補間差と位置推定精度の校正用プローブ
requirements.txt      この環境で試験した主要依存関係
stats_suite/          統計試験のsummary.json、objects.csv、各回の記録
retry_suite/          前版（再試行導入時）の比較試験記録。参考として同梱
calibration_probe.json  校正プローブの実測値
検査結果.json          同梱ソース・記録・圧縮ファイルの機械検査結果

改良版はコードと試験記録の一式です。動画は含みません。録画機能は保持し、
別途 run_sorting.py を既定引数で実行すると前版と同じ字幕付きMP4が得られます。

２．推奨環境
Python 3.11、ffmpeg（録画時のみ）、日本語フォント、インターネット接続。
検証環境はLinux・Python 3.11・CPUのみ。WindowsやmacOSでは未検証。
日本語フォントが自動検出できない場合は --font で指定する。
初回はHugging Faceからモデルを取得する。モデル重みはこの一式には含めない。

３．導入例
python3.11 -m venv .venv

Linux/macOS:
source .venv/bin/activate

Windows:
.venv\Scripts\activate

CPU用のPyTorchを先に導入:
python -m pip install torch==2.9.0 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements.txt

ffmpegは録画時のみ必要。Linuxの例:
sudo apt-get install ffmpeg fonts-noto-cjk

４．実行
録画を省略した物理動作試験:
python run_sorting.py --no-video --output smoke_test

本番の録画:
python run_sorting.py --output output

３視点合成の録画（俯瞰＋真上＋手先。録画専用で推論には使わない）:
python run_sorting.py --multi-view --output multiview_video

把持失敗の検知と再試行を試す（各物体の初回だけ指が閉じない故障を注入）:
python run_sorting.py --no-video --fault first-open --max-attempts 2 --output retry_demo

未知色による保留判断を試す（２個目が紫になる）:
python run_sorting.py --no-video --colors red,purple,green --output hold_demo

４条件×３回の統計付き自動試験:
python test_suite.py --output stats_suite --repeats 3

保留判断・射影・入力検査など11件の検査:
python -m unittest test_logic -v

候補間差と位置推定精度の校正プローブ:
python calibration_probe.py

注意: --max-attempts は再試行回数ではなく初回を含む総試行回数です。
２なら初回＋再試行１回。上限４回。既定は２回。
--allow-failures は物理的失敗の終了コードだけを変え、実装例外は隠しません。
既定では３個の処理が完了しないと記録後にエラー終了します。

５．設計と限界
・画像と言語のモデルCLIPに、各供給位置のカメラ画像と４つの候補文章を渡す。
・候補は赤・緑・青・紫。紫は「どの色でもない」を表す未知色の候補。
・予測が未知色、または候補間差がしきい値（既定0.5）未満なら仕分けを保留し、保留皿へ置く。
・保留皿は中立色。保留された物体は色の皿へ運ばない。
・保留判断の根拠は校正プローブで測定。通常光・薄暗光・未知色の候補間差は0.92〜0.99だった。
・しきい値未満の実際の発生例は今回の試験条件にない。しきい値は安全網であり、
  保留の実際の発火は未知色の候補（purple）経由で確認している。
・相対スコアは候補集合内の値であり、実世界で校正した正解確率ではない。
・位置推定は真上カメラのHSV色付き塊の重心。深層学習の物体検出ではない。
・推定は失敗後の再接近先の決定だけに使用。初回の供給位置は既知治具のまま。
・推定精度は校正プローブで最大誤差5.2mm（ずれ6cmまでの5条件）。探査範囲は治具中心±9cm。
・物体が探査範囲を外れた場合は estimate_unavailable として中止する。
・軽い滑り条件（摩擦0.4）は再試行の対象。極端な低摩擦（0.05）では物体が飛び出し、
  回復不能として安全に中止する。前版の試験で確認済み。
・アームは逆運動学と関節位置制御。持ち運びは左右の指の接触・摩擦だけを使う。
・物体を瞬間移動させる処理、把持時の固定拘束、正解色による認識の代替は使わない。
・把持後は0.1秒間隔の３回連続で両指接触と物体中心高さ12cm超を確認する。
・失敗時は指を開いて待ち、退避。治具付近に残る場合は治具へ、離れた場合は推定位置へ再接近。
・接触・高さ・再試行可否の位置はシミュレータから取得。画像だけでの自律復旧ではない。
・推定位置とシミュレータ位置の両方を記録する。後者は精度評価専用で制御には使わない。
・搬送先到着時にも接触と高さを確認し、保持喪失時は中止する。搬送中の全時点の連続監視ではない。
・配置・分類の誤りや搬送後落下は記録するが、自動で拾い直す処理は_exists_nearby場合のみ。
・すべり検知: 持ち上げ・搬送中を0.25秒間隔で監視し、保持中の高さが走行最大から8mm超
  低下したらすべりと判定し、把持力を1.6倍ずつ強める（上限2.5倍）。
・弱い把持力（3N）では搬送中にすべりを検知し、力を強化して仕分けを継続できた（実測）。
・低摩擦0.4の押し出しは把持の閉じる段階で起こるため、すべり検知では防げない（実測0/3）。
・統計試験は各条件・各回３物体を複数回。故障注入や低摩擦は試験条件であり自然故障率ではない。
・小規模試験であり、成功率の推定や実機での性能ではない。
・モデルの追加学習、未知物体の姿勢変化、実機への適用は検証していない。
・retry_eventsは初回以外の把持実行数、recovered_objectsは初回失敗後に最終成功した物体数。
・estimate_eventsは推定位置への再接近を実行した回数。

６．PDFの課題ルールに対する確認
対象資料: 最終課題（10_19 改訂版）.pdf
・動画の長さは１〜３分以内。録画時は検査結果と動画で確認する。
・AIの使用は必須、学習は任意。この実装は事前学習済みCLIPの実推論を使う。
・PyBulletは講義外ツールだが、資料では他のツールを許可している。
・コード一式だけで提出完了にはならない。別途、レポートPDFが必要。
・レポート名: 説明資料_PAI最終課題_omnicampusアカウント名.pdf
・GitHubへコードを公開設定で登録し、リポジトリURLを提出する。
・YouTubeへMP4を限定公開または公開で投稿し、URLを指定フォームに提出する。
・YouTubeのタイトル: PAI最終課題_omnicampusアカウント名 または アカウントID
・個人情報を含めない。個人名をアカウント名にしている場合はアカウントIDを利用。
・子ども向け・年齢制限は「いいえ」。インスタントプレミアム公開にしない。
・予約公開の場合は締切までに公開し、採点完了まで削除・非公開変更をしない。
・資料記載の締切: 2026年11月2日 AM10:00。更新がないか提出先で確認する。
・サンプルの丸写しは禁止。自分で理解・改良し、工夫と制限をレポートに明記する。
・この一式には提出用レポートPDFは含まない。今回の実装支援と課題全体の提出を区別する。
・自動でGitHub公開やYouTube投稿をするコードではない。

https://huggingface.co/docs/transformers/en/model_doc/clip

ロボット形状・URDFはpybullet_data付属のfranka_panda/panda.urdfを使用。
この一式はロボット形状やCLIP重みの著作権を主張しない。
公開・再配布時には依存ライブラリ、モデルおよび各資産のライセンスを確認する。
独自に実装した部分は、治具配置、色判定と搬送先の接続、保留判断、摩擦把持の制御、
失敗検知と上限付き再試行、画像による位置推定と再接近、統計試験、結果記録、
字幕付き録画、出力検査。講義サンプルのコードは取得・転用していない。

８．読み替えてはいけない結果
結果記録が成功でも、対象パソコンでの動作まで確認したわけではない。
録画した動画は提出前に通して再生し、字幕、アーム動作、最終位置を自分でも確認する。
AIの使用や本支援については講座の方針に従って説明し、理解せずそのまま提出しない。

障害物越えの録画（低い壁＋経由点経路。通常の把持力を推奨）:
python run_sorting.py --multi-view --wall --output wall_video
注意: 把持力を極端に弱くしたままだと、越え搬送の途中で保持を失う（実測）。
